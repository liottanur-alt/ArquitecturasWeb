
# Project Instructions

## General principles
- Keep solutions simple and avoid unnecessary complexity.
- Do not introduce dependencies unless they are strictly necessary.
- Do not add libraries, frameworks, design patterns or abstractions without a clear reason.
- Reuse existing code and project structure whenever possible.
- Do not duplicate existing functionality.
- Do not create files unless they are actually needed.

## Before making changes
- First analyze the existing code and understand its architecture.
- Check how similar functionality is already implemented.
- Do not modify files unrelated to the requested task.
- If the requested change requires a significant architectural decision, explain it and ask before proceeding.

## Coding
- Follow the existing coding style and naming conventions.
- Do not overengineer solutions.
- Avoid unnecessary methods, classes and interfaces.
- Do not add comments that simply repeat what the code does.
- Do not refactor working code unless explicitly requested.

## Dependencies
- Always check whether existing dependencies already provide the required functionality.
- Never add a dependency just for convenience when a simple existing solution is sufficient.
- Explain why a new dependency is necessary before adding it.

## Execution
- Do not run unnecessary commands.
- Do not execute the entire test suite when a focused test is sufficient.
- Never delete or overwrite existing files without asking.
- Never commit or push changes unless explicitly requested.

## Communication
- Explain what you intend to change before implementing significant modifications.
- If something is unclear, ask instead of making assumptions.
- Keep explanations concise and technical.
- Do not implement additional features that were not requested.
